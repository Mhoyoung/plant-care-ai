# 제안과 실제 관리 연결

한 식물의 AI 제안, 실제로 한 관리, 이후 관찰을 연결해 다음 분석에 참고합니다.
이 연결은 저장한 기록을 분석 문맥으로 전달하는 방식입니다. 모델 자체를 학습시키는 기능은 아닙니다.

## 사용 순서

1. 식물 상세의 **AI 분석** 탭에서 상태·질문과 선택 사진을 보내 분석합니다.
2. 새싹 안내와 **먼저, 이것부터 확인해요** 카드를 읽습니다. **확인 후 할 수 있는 관리**를 펼쳐 제안의 조건을 살펴봅니다.
3. 펼친 제안의 **관리 기록 남기기**를 누르면 **관리 기록** 탭에서 그 제안을 선택한 상태로 열립니다.
4. 실제로 한 관리 종류와 날짜, 메모를 입력하고 **실행 기록 저장**을 누릅니다. 실행 메모는 필수입니다.
5. 나중에 변화를 관찰하면 **이후 상태 남기기**에서 **좋아졌어요 / 비슷해요 / 나빠졌어요 / 아직 모르겠어요**와 메모·사진을 남깁니다.
6. 다음 **Gemini로 분석**을 요청할 때 이전 제안과 실행·관찰을 함께 보냅니다.

물을 주지 않고 지켜본 경우에는 관리 종류를 **상태 관찰**로 선택하고 실제로 확인한 내용을 적습니다.
제안을 눌렀다는 이유로 물주기나 실행 완료를 자동 저장하지 않습니다.
실제로 새 물주기를 했으면 일반 관리 기록 또는 새 분석의 제안에 별도 기록으로 남깁니다.

## 화면에서 확인할 것

- **AI 분석:** 각 제안에 실행 날짜·종류, 최근 경과, 이후 관찰 기록과 사진을 표시합니다.
- **한눈에 보기:** 실행 기록이 연결된 최근 제안 최대 3건을 보여줍니다.
- **관리 기록:** 일반 기록·AI 제안 실행·실행 후 경과 중 선택합니다. 타임라인에서도 연결한 제안을 확인할 수 있습니다.
- **분석 상세:** 분석 당시 참고한 이전 제안과 실행·경과를 확인할 수 있습니다. 나중에 추가한 기록이 과거 분석 입력을 바꾸지는 않습니다.

## 기록 규칙

제안 하나에는 실행 기록 한 건을 연결하며, 이후 관찰은 여러 번 남길 수 있습니다.
해당 식물의 제안만 연결할 수 있고, 실행은 제안 당일부터, 경과는 실행 당일부터 기록합니다.
날짜는 한국 시간(Asia/Seoul) 기준이며 미래 날짜는 저장하지 않습니다.
경과는 **상태 관찰**로 저장합니다. 아직 상태를 모르면 메모나 사진으로 확인한 내용을 남겨 주세요.
기존 일반 기록은 유지하며, 앱이 임의로 AI 제안에 연결하지 않습니다.
상태가 좋아졌다는 관찰만으로 특정 관리가 원인이라고 확정하지 않습니다.

## 다음 분석과 보관

현재 요청에는 최근 관리 기록 최대 30건, 최근 제안 최대 10건과 각 제안의 실행·최근 관찰 최대 3건을 포함합니다.
실행 기록이 없는 제안은 미확인으로, 경과가 없는 실행은 이후 상태 미확인으로 구분합니다.
로컬 DB ID·사진 경로, 과거 분석 입력 전체와 과거 사진 전체는 보내지 않습니다.
요청은 분석 버튼을 눌렀을 때만 발생합니다. 실행·경과 기록 저장, 조회, 탭 이동은 API를 호출하지 않습니다.

JSON 내려받기의 `schema_version`은 2입니다. `ai_suggestions`에 제안과 실행·관찰을,
`care_logs`에 `suggestion_id`와 `link_type`을 포함합니다. 사진 파일은 별도 백업해야 합니다.
기존 DB는 앱 시작 시 필드를 추가해 갱신합니다. 로컬 업데이트 전에는 앱 종료 후 `data/`를 복사하세요.
현재 로그인한 정원은 **기록 보관과 백업**에서 사진 포함 전체 ZIP을 내려받습니다. [저장소 안내](CLOUD_STORAGE.md)

현재 테스트는 임시 데이터와 모의 API를 사용해 저장·재조회·다음 분석 입력까지 확인합니다.
지역 실외 날씨도 선택적으로 분석에 포함할 수 있습니다. [날씨 안내](WEATHER.md)
실제 식물의 장기 경과와 날씨를 반영한 분석 품질은 추가 검증 단계입니다.

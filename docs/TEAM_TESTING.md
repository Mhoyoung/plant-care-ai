# 팀원 사용·테스트 안내

공유 앱: **[내 식물 기록 열기](https://plant-care-ai-bh5dtxenovacdz7hc4bdvj.streamlit.app/)**

## 접속과 준비

앱 관리자가 초대한 이메일 계정으로 접속합니다. 로그인이나 접근 권한 안내가 나오면 초대 계정을 확인하고,
접속되지 않으면 관리자에게 알려 주세요. Python·Git 설치나 개인 Gemini/Supabase 키 준비는 필요하지 않습니다.
앱 자체의 별도 회원가입은 없으며, 현재는 하나의 팀 정원을 함께 사용합니다.
팀원들이 등록한 식물·메모·사진·분석을 서로 볼 수 있으므로 개인 자료를 넣기 전에 공유 범위를 확인하세요.

실제 식물이 없어도 화면 사용성과 AI 비교를 테스트할 수 있습니다.
등록·기록 시험용 식물은 `[테스트] 이름_식물`처럼 구분하고 메모에 **가상 데이터이며 실제 관찰이 아님**을 적어 주세요.
현재 예시 몬스테라와 테스트 사진·기록도 실제 식물의 관찰이나 관리 효과를 보여주는 자료가 아닙니다.
다른 팀원의 기록을 자신의 실행 기록으로 사용하지 마세요.

## 10분 사용성 테스트

가능하면 휴대폰에서 먼저 사용하고, 설명을 듣기 전에 아래 과제를 따라 해보세요.

| 과제 | 화면에서 할 일 | 남길 피드백 |
|---|---|---|
| 식물 찾기 | 내 정원에서 카드를 열어 마지막 물주기·관리 기록 찾기 | 찾는 데 걸린 대략적인 시간, 헷갈린 이름 |
| 등록·기록 | 새 식물을 등록하고 오늘 상태·메모 저장하기 | 필수 입력, 저장 버튼, 완료 표시를 이해했는지 |
| AI 안내 읽기 | 저장된 분석의 새싹 안내·확인 카드·관리·한계·전체 분석 펼쳐보기 | 먼저 무엇을 확인해야 하는지 자신의 말로 설명 |
| 제안 연결 | 관리 제안의 **관리 기록 남기기**를 눌러 연결한 제안 확인하기 | 일반 기록과 제안 실행의 차이를 알겠는지 |
| 다시 확인 | 내 정원으로 돌아가 기록 조회, 필요하면 새로고침 | 입력한 내용이 남아 있는지, 가로 스크롤·잘림이 있는지 |

제안 버튼을 누르는 것만으로 실행이 저장되지는 않습니다. 실제로 한 관리만 실행으로 기록하세요.
시험용으로 저장할 때는 메모에 가상 기록임을 명시합니다. 이후 경과도 관찰한 내용만 남깁니다.
사진은 선택입니다. 저장된 분석을 읽는 과제는 Gemini를 새로 호출하지 않습니다.
AI 안내 읽기·제안 연결 과제는 저장된 분석이 있는 예시 식물에서 진행할 수 있습니다.

## AI 제안 평가

**AI 비교 → 예시 사례**에는 젖은 흙, 마른 흙, 이전 관리 후 경과가 있는 세 상황이 있습니다.
AI를 호출할 차례와 담당자는 팀에서 먼저 정하세요. 같은 프로젝트의 한도를 함께 사용합니다.

1. 한 사례를 선택하고 **비교 준비**로 입력을 고정합니다.
2. 입력과 Google 전송 안내를 확인한 뒤 동의합니다.
3. **기록 없이 분석**, **기록 포함 분석**을 각각 요청합니다. 둘 다 실행하면 총 2회입니다.
4. 아래 기준으로 두 답변을 읽고 화면의 평가와 이유를 남깁니다.
5. 새로고침·새 실험 전에 **비교 기록 내려받기**로 보관합니다. 사진을 썼다면 사진도 따로 내려받습니다.

| 평가 기준 | 확인할 질문 |
|---|---|
| 기록 반영 | 물 준 시점·실제 실행·경과를 맞게 읽었나요? 미확인을 실패나 완료로 바꾸지 않았나요? |
| 없는 사실 | 보지 않은 사진·측정하지 않은 흙 수분·확인하지 않은 회복이나 병명을 사실처럼 말하나요? |
| 확인 조건 | 물주기 전에 무엇을 확인하고, 어떤 경우에 어떤 행동을 해야 하는지 알 수 있나요? |
| 이해도 | 새싹 안내와 카드를 읽고 다음 행동을 설명할 수 있나요? 펼쳐보기에서 근거와 한계를 찾을 수 있나요? |

기록 포함 답변이 무조건 더 좋다고 평가하지 않습니다. 사례별 문제가 있는 문장과 이유를 남겨 주세요.
사용자의 이해도 평가, 원예 자료와 내용 비교, 실제 식물의 여러 날 관찰은 서로 다른 검증입니다.
가상 입력에 대한 답변이나 한 번의 호전 기록을 실제 진단 정확도·회복 효과로 발표하지 않습니다.
자세한 입력 통제와 한계는 [AI 비교 안내](AI_COMPARISON.md)에 있습니다.

## 문제가 생기면

| 상황 | 먼저 할 일 |
|---|---|
| 접속 권한·로그인 안내 | 초대받은 이메일인지 확인하고 앱 관리자에게 알리기 |
| AI 버튼 비활성 또는 키 설정 안내 | 공유 앱의 관리자가 서버 설정 확인. 팀원이 키를 채팅에 보내지 않기 |
| 429 한도 오류 | 화면의 원인·대기 안내 기록, 담당자가 프로젝트 한도 확인. 버튼 연속 클릭 피하기 |
| 시간 초과·응답 실패 | 자동 재시도하지 않음. 요청이 서버에서 처리됐을 수 있으므로 담당자와 재요청 여부 정하기 |
| 저장 충돌·결과 불확실 | 저장하려던 메모를 개인적으로 복사해 두고, 새로고침 후 기록이 이미 있는지 먼저 확인 |
| 사진이 안 보임·저장소 오류 | 화면의 안내와 발생 시각을 관리자에게 전달. 기존 기록을 다시 등록하지 않기 |

공유 앱의 API 키·저장소·접근 설정은 관리자가 담당합니다.
백업은 **기록 보관과 백업**에서 전체 정원 ZIP으로 준비합니다. 개인 기록이 포함되므로 공개 저장소에 올리지 않습니다.
비교 실험은 이 ZIP에 포함되지 않으며 별도로 내려받아야 합니다.

## 피드백 양식

아래 내용을 [GitHub Issue](https://github.com/Mhoyoung/plant-care-ai/issues) 또는 팀에서 정한 보고 경로에 남겨 주세요.
GitHub 보고에는 계정과 저장소 접근 권한이 필요합니다. 스크린샷에서는 개인정보와 비밀키를 가립니다.

```text
종류: 사용성 / 기능 오류 / AI 제안 내용
휴대폰·브라우저:
발생 시각:
어떤 화면에서 무엇을 했나요?:
기대했던 결과:
실제로 나온 결과:
다시 해보는 순서:
AI 내용 문제라면 해당 문장과 판단 이유:
```

현재는 개인별 정원, 자동 알림, 식물 삭제·기존 기록 편집 기능이 없습니다.
잘못 저장한 테스트 기록은 해당 식물 이름·시각·내용을 관리자에게 알려 정리 대상으로 남겨 주세요.
설치해서 코드를 수정하려면 [로컬 실행 안내](RUNNING.md)를 참고하세요.

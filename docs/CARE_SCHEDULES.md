# 케어 일정과 휴대폰 캘린더

## 사용 순서

1. **내 정원 → 식물 살펴보기 → 케어 일정**을 엽니다. 예정이 없으면 **직접 일정 추가** 입력칸이 바로 보이며, 기존 일정이 있으면 **새 케어 일정**을 펼칩니다.
2. 관리 종류, 할 일, 예정 날짜·시간, 선택 메모를 입력합니다. 시간은 **한국 기준**입니다.
3. 정원의 **다가오는 케어**에서 오늘·지난 일정과 가까운 일정을 확인합니다. 지난 일정도 자동 완료되지 않습니다.
4. 일정의 **휴대폰 캘린더에 추가**를 펼쳐 Google 캘린더 추가 화면을 열거나 `.ics` 파일을 내려받습니다.
5. 실제로 관리한 뒤 **실제로 관리했어요 → 실제 종류·날짜·한 일 → 완료하고 관리 기록 저장**을 누릅니다.

예정 종류가 물주기였어도 흙이 젖어 있어 물을 주지 않았다면 실제 종류를 **상태 관찰**로 바꿉니다.
일정 등록 자체는 물주기 이력이나 AI 참고 기록을 만들지 않습니다. 완료 기록은 실제 관리 타임라인과 다음 AI 요청에 반영됩니다.
계획과 완료 기록은 같은 팀 정원에 저장되며 팀원 모두 볼 수 있습니다.

## AI 제안에서 일정 만들기

**AI 분석 → 확인 후 할 수 있는 관리 → AI 제안으로 일정 만들기**를 누르면 해당 식물의 케어 일정에 초안을 엽니다.
케어 일정 탭의 **AI 제안에서 일정 만들기**에서도 저장된 제안을 바로 고를 수 있습니다. 아직 저장한 제안이 없으면 분석 화면으로 이동하는 버튼을 표시하며, 이동만으로 AI를 호출하지 않습니다.
원래 제안·확인 사항·분석 한계를 함께 보여주고, 제목은 **흙 상태·물주기 조건 확인**처럼 확인할 주제로 짧게 채웁니다. 제목은 직접 수정할 수 있으며 관리 실행을 확정하는 명령이 아닙니다.
Google 캘린더와 `.ics`의 설명에는 **AI 제안 원문 → 먼저 확인할 것 → 분석의 한계 → 추가 메모**를 생략 없이 넣습니다. 일정 카드에서 캘린더에 들어갈 AI 설명을 미리 확인할 수 있습니다.
설명이 길어 앱의 링크 길이 기준을 넘으면 Google 추가 링크 대신 전체 내용이 담긴 `.ics` 파일을 안내합니다. 원문이나 확인 조건을 잘라내지는 않습니다.
관리 종류와 날짜는 자동 확정하지 않습니다. AI가 시간대를 추천한 내용이 있으면 원문을 참고해 사용자가 날짜·시간을 정하고 확인 체크 후 저장합니다.
이 기능은 이미 저장한 AI 응답을 사용하므로 추가 API 요청이나 비용이 생기지 않습니다. 날짜·반복 주기를 AI가 새로 생성하는 기능과는 구분합니다.

같은 제안으로 예정된 일정을 중복해서 만들지 못하게 하고, 실제 완료하면 원래 AI 제안의 실행 기록으로 연결합니다.
따로 실행 기록을 먼저 남겼다면 중복 완료를 막으므로 남은 일정은 취소해 정리합니다. 완료 후에는 관리 기록 탭에서 해당 제안의 경과 관찰을 남길 수 있습니다.
캘린더는 확인할 시점을 알려 주는 역할이며 실행 전 앱에서 원래 제안의 조건을 다시 확인합니다.

## 휴대폰 알림 설정

- **Google 캘린더**: 추가 화면에서 내용을 확인하고 저장하기 전에 원하는 알림 시간을 설정합니다.
- **Apple·다른 캘린더**: `.ics` 파일을 지원하는 캘린더에서 열어 가져옵니다. 파일에는 시작 **10분 전 알림 요청**이 들어 있습니다.
- Google 캘린더에서 파일 가져오기는 PC 웹의 **설정 → 가져오기 및 내보내기**를 사용할 수 있습니다. 휴대폰에서 같은 계정의 캘린더 동기화를 확인합니다.
- 캘린더에 따라 파일의 알림 요청을 무시하거나 자체 기본값을 적용할 수 있습니다. **가까운 시각의 테스트 일정을 하나 추가해 휴대폰에서 알림을 받는지 확인**합니다.
- 휴대폰 설정에서 해당 캘린더 앱의 알림 권한과 캘린더 표시·동기화를 확인합니다.

앱은 Google 계정에 직접 접근하거나 일정·알림을 자동 전송하지 않습니다. Google 추가 링크에는 해당 식물 이름·할 일·일정 메모와 연결된 AI 제안·확인 조건·분석 한계가 들어가며, 사용자가 링크를 열고 저장합니다.

## 수정·취소와 제한

일정 카드의 **일정 수정·취소**에서 변경합니다. 취소는 확인 체크 후 처리하며 이력은 남습니다.
완료·취소한 일정은 다시 실제 관리로 저장하지 못하게 하고, 완료 저장은 일정 상태와 관리 기록을 한 번에 반영합니다.

**앱과 휴대폰 캘린더는 자동 동기화되지 않습니다.** 앱에서 변경·취소·완료해도 이미 추가한 캘린더 이벤트는 그대로 남습니다. 캘린더에서도 직접 수정·삭제해야 합니다.
이전에 저장한 긴 제목은 자동으로 바꾸지 않습니다. 앱의 **일정 수정·취소**에서 제목을 짧게 바꿀 수 있고, 기존 Google 일정은 직접 수정하거나 새 내용으로 다시 추가해야 합니다. 다시 추가할 때는 중복 일정에 주의하세요.
반복 일정, 앱 자체 푸시, 개인별 알림 구독은 아직 지원하지 않습니다. 앱 자체 푸시는 설치 가능한 웹앱·서비스 워커·구독 저장·예약 발송을 다음 단계로 설계합니다.

새 일정은 전체 정원 ZIP과 식물별 JSON에 포함됩니다. 기존 일정 없는 정원·백업도 계속 읽으며, Supabase의 기존 SQL을 다시 실행할 필요가 없습니다.
새 형식으로 저장된 정원은 최신 앱 코드로 사용하세요. 이전 앱 코드로 되돌리기 전에는 백업과 스냅샷 형식 호환성을 확인합니다.

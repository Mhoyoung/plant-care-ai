# 모바일에서 먼저 사용하는 관리 흐름

식물 앞에서 사진을 찍고 관리 직후 기록하는 사용을 우선합니다. 현재는 휴대폰 브라우저용 웹 시제품이며,
앱스토어 출시·앱 자체 푸시·오프라인 사용은 별도 작업입니다. 개인 정원은 [이메일 로그인](ACCOUNTS.md)으로 구분합니다. 케어 일정의 휴대폰 알림은 [캘린더 연동](CARE_SCHEDULES.md)으로 시작합니다.

## 참고와 적용

사용자가 지정한 [순룸](https://a7.scnuoss.net/#/login)을 PC와 390px 화면으로 확인했습니다.
큰 제목·넉넉한 여백·명확한 행동 버튼과 단계별 정보 배치를 참고하고 기존 식물 앱의 초록/아이보리 색은 유지합니다.
모바일의 목록/지도 전환처럼 정보를 단계별로 보여주는 원칙을 적용합니다. 일부 매물 조회 오류가 있어 모든 서비스 흐름을 검증한 것은 아닙니다.
참고 사이트의 로고·사진·문구·소스 코드는 복제하지 않습니다.

- 상단 **내 정원 / 새 식물 / AI 비교**는 서버 재실행 없이 브라우저에서 전환하는 탭입니다. 세 패널을 처음에 준비하므로 첫 화면 준비 시간이 조금 늘 수 있지만 이후 상단 탭 전환은 원격 조회를 기다리지 않습니다.
- 탭만 바꿀 때 작성 중인 등록 입력과 비교 결과를 유지합니다. 등록이 성공하면 식물 상세로 이동하고 등록 폼은 새 입력을 위해 비웁니다. 사이드바의 **정원의 식물**은 정원 패널에서 볼 식물을 선택합니다.
- 선택한 탭은 배경색으로 구분하고 내용은 140ms의 짧은 페이드로 표시합니다. 운영체제의 동작 줄이기 설정에서는 전환 효과를 끕니다.
- 정원의 **오늘 챙길 일**에서 예정된 일정을 확인하고, **관리 후 변화도 확인해 주세요**를 펼쳐 실행한 제안의 경과를 이어 기록합니다. 일정이 없으면 오늘 상태 남기기로 관찰을 시작합니다. 물주기 날짜만으로 자동 작업을 만들지 않습니다.
- 식물 카드와 상세의 **오늘 상태 남기기**는 상태 관찰 폼을 열며, 버튼만 눌러 기록을 생성하지 않습니다.
- 상세 상단의 **AI로 살펴보기**는 분석 탭을 열며, 분석 버튼과 전송 동의 전에는 호출하지 않습니다.
- 휴대폰에서는 카드·입력 폼·비교 결과를 한 열로 표시하고, 주요 버튼과 탭은 최소 48px 높이를 확보합니다.
- 홈의 식물·관리 기록·AI 관찰 수는 요약 배너의 한 줄로 표시합니다. 상세의 핵심 숫자는 세 칸에 표시하고 긴 설명·입력 상세·백업은 필요할 때 열어봅니다.

## 홈 화면 정리 · 2026-10-28

초록/아이보리 분위기를 유지하며 큰 소개 배너와 반복되는 안내를 줄였습니다.
홈은 **정원 요약 → 오늘 챙길 일과 AI 안내 → 나의 식물** 순서입니다.

- PC에서는 오늘 일정과 AI 안내를 나란히, 식물 카드를 세 열로 배치합니다. 600px 이하에서는 한 열로 표시하며 AI 안내 설명을 줄여 식물 목록까지의 스크롤을 줄입니다.
- 일정에는 날짜·시간·식물 이름과 짧은 제목을 표시합니다. **일정 보기**는 해당 식물의 케어 일정 탭을 열며 완료 기록을 만들지 않습니다.
- **내 식물 AI로 살펴보기**는 안내에 명시된 첫 식물의 분석 화면을 엽니다. 다른 식물은 각 카드에서 선택합니다. 버튼만 누를 때 AI 요청이나 기록 저장은 없습니다.
- **식물 등록** 버튼은 목록 제목 옆에 두고, 빈 정원에서는 첫 식물 등록 안내와 예시 비교 진입을 제공합니다.
- 식물 카드의 사진·이름·장소·물주기·기록 수와 상세/관찰 버튼을 유지합니다. 개인 사진의 전달 방식과 로그인·데이터 분리는 변경하지 않습니다.

화면 점검에는 실제 개인 기록과 구분한 로컬 가상 식물·일정을 사용합니다. 브라우저 크기 점검은 실제 휴대폰의 터치·키보드·카메라 시험을 대신하지 않습니다.

AI 결과는 새싹 아이콘의 짧은 안내, 확인 카드 최대 3개, 펼쳐보는 추가 항목·조건부 관리·한계·전체 분석으로 표시합니다.
확인 카드에는 원문을 그대로 표시해 조건을 줄이거나 빠뜨리지 않습니다. 기존 분석·비교 결과·다운로드 원문은 바꾸지 않습니다.
새 분석에는 핵심을 1–2개의 짧은 문장으로 작성하도록 요청하지만 중요한 조건과 주의사항은 유지합니다.
화면 표시에는 새 AI 호출이 필요하지 않으며 분석/비교 양쪽에 같은 표시 규칙을 사용합니다.
마스코트의 이름·성격·움직임은 후속 범위입니다. [유사 서비스와 참고 방향](COMPETITORS.md)을 함께 확인하세요.

## 확인할 기준

390px/844px 휴대폰 크기와 PC 화면에서 정원→상태 관찰, 상세→분석, 예시 비교 준비를 확인합니다.
레이아웃·문구·전송 동의·실패 안내와 기존 등록/기록 흐름을 검증하며, 실제 기기의 카메라·키보드·터치 동작은 팀원 테스트로 보완합니다.

탭 방식 참고: [Streamlit tabs](https://docs.streamlit.io/develop/api-reference/layout/st.tabs)

## 2026-10-15 코드 점검과 남은 실화면 확인

- 상세 탭 4개(한눈에 보기·관리 기록·AI 분석·케어 일정)는 좁은 화면에서 동일 비율, 48px 이상의 터치 높이와 줄바꿈을 사용합니다.
- 예정된 일정이 없으면 빈 상태 안내와 직접 입력 폼을 바로 보여줍니다. 케어 일정 탭에서도 저장된 AI 제안을 선택해 초안을 만들 수 있으며, 별도 로컬 시연 자료는 공유 정원에 복제하지 않습니다.
- 일정 날짜·시간 입력은 모바일에서 한 열로 쌓고 Google 캘린더 링크·다운로드·저장 버튼은 누르기 쉬운 높이를 유지합니다.
- 작은 보조 설명, 관리 종류 배지와 카드 메모를 모바일에서 13px로 보완하고 긴 식물 이름·일정 제목은 줄바꿈합니다.
- 메뉴는 제목과 함께 스크롤되며 맨 위로 버튼은 충분히 내려갔을 때만 나타납니다. 캘린더 연결이나 화면 이동만으로 AI를 호출하지 않습니다.

브라우저 조작 도구가 현재 URL을 확인하지 못해 자동 화면 점검은 중단됐습니다. 2026-10-15 사용자가 제공한 Chrome 390×844 캡처에서 정원·다가오는 일정·케어 일정 카드·캘린더 버튼의 한 열 배치와 줄바꿈을 확인했습니다. 첫 캡처에는 브라우저 번역이 적용돼 있었고, 원문 보기로 바꾼 추가 캡처에서 문구를 확인했습니다. 앱의 기본 언어도 한국어로 지정했습니다.

등록·기록·일정의 입력/오류/저장 흐름은 Streamlit AppTest로 검증했습니다. **320/430px 실화면, 실제 휴대폰의 터치·키보드·카메라·캘린더 알림 수신은 미완료**이며, 캡처 확인을 실제 기기 전체 점검으로 간주하지 않습니다.

다음 실화면 점검에서는 정원 → 식물 선택 → 기록/AI/일정 → 새 식물 → AI 비교를 각각 열어 가로 넘침·작은 글씨·키보드가 입력/저장 버튼을 가리는지 확인합니다.
케어 일정의 추가·수정·빈 입력 오류·완료·취소와 캘린더 가져오기 후 실제 알림 수신까지 확인해야 합니다. 화면 크기 모의 테스트만으로 휴대폰 알림 수신을 검증할 수 없습니다.

# 팀원 사용·테스트 안내

공유 앱: **[내 식물 기록 열기](https://plant-care-ai-bh5dtxenovacdz7hc4bdvj.streamlit.app/)**

## 접속과 준비

**회원가입 → 이메일 인증 → 로그인**으로 본인 정원을 엽니다. [계정 설정](ACCOUNTS.md) 적용과 실제 가입 검증이 완료된 앱에서 진행합니다. 메일이 오지 않으면 반복 가입하지 말고 관리자에게 SMTP·메일 한도 확인을 요청하세요.
Python·Git 설치나 개인 API 키 준비는 필요하지 않습니다. 각자 자기 식물·사진·기록·일정만 볼 수 있으며 다른 사람 자료는 보이지 않아야 합니다.

실제 식물이 없어도 화면 사용성과 AI 비교를 테스트할 수 있습니다.
등록·기록 시험용 식물은 `[테스트] 이름_식물`처럼 구분하고 메모에 **가상 데이터이며 실제 관찰이 아님**을 적어 주세요.
기존 공동 정원의 예시 몬스테라는 개인 정원으로 자동 이전되지 않습니다. 가상 자료는 실제 관리 효과를 입증하지 않습니다.
다른 팀원의 기록을 자신의 실행 기록으로 사용하지 마세요.

## 휴대폰 테스트 진행표

첫 회차는 **기본 사용 15–20분 + 캘린더 알림 대기**로 잡습니다. 팀원 A·B·C와 팀장이 각자 사용한 기종·OS·브라우저를 적습니다.
실제 Android/iPhone이 있는 범위에서 나눠 확인하고, 사용하지 않은 기기를 통과로 표시하지 않습니다.
결과는 **미실행 / 통과 / 문제 / 보류** 중 하나로 기록합니다. 아직 팀원 모바일 테스트 결과는 수집 전입니다.

### 시작 전

1. 본인 이메일 가입·인증·로그인을 확인합니다. 팀원이 개인 API 키를 준비할 필요는 없습니다.
2. 본인 자료는 `[테스트] A_식물`처럼 이름을 구분하고, 메모에 **가상 입력이며 실제 관찰이 아님**을 적습니다.
3. 본인 테스트 식물만 변경합니다. 다른 계정의 자료가 보이면 테스트를 멈추고 관리자에게 알립니다. 가상 사례 읽기는 AI 비교의 예시를 사용합니다.
4. 알림 시험용 일정은 현재보다 **10–15분 뒤**, 캘린더 알림은 **5분 전**으로 설정합니다. 화면의 날짜와 한국 시간을 직접 확인합니다.

### 각자 진행할 기본 과제

| ID | 순서 | 확인할 항목 |
|---|---|---|
| M01 | 공유 앱 접속 | 가입·이메일 인증·로그인이 가능한가? 로그인·접속 안내를 이해하는가? |
| M02 | 내 정원에서 식물 찾기 | 마지막 물주기·관리 기록·AI 관찰을 찾을 수 있는가? |
| M03 | 본인 테스트 식물 등록 | 이름·장소·가상 상태 입력, 필수 항목과 저장 성공 안내가 명확한가? |
| M04 | 상태 관찰 기록 저장 | 테스트 메모가 1건 생기고, 물주기 날짜는 그대로인가? |
| M05 | 선택 사진과 재접속 | 개인 정보 없는 사진/시험 이미지를 첨부하면 새로고침 후 사진·메모가 남는가? 사진이 없으면 이 항목은 보류하고 이유를 적는다. |
| M06 | AI 비교 예시 또는 본인 식물의 저장된 분석 읽기 | 먼저 확인할 사항·조건에 맞는 관리·분석 한계를 자기 말로 설명할 수 있는가? 읽기만으로 새 AI 요청이 발생하지 않는가? |
| M07 | 본인 식물에 직접 케어 일정 생성 | 짧은 제목·날짜·시간이 맞는가? 일정만 저장하면 관리 기록은 늘지 않는가? |
| M08 | 휴대폰 캘린더에 추가 | Google 추가 화면 또는 지원하는 .ics 가져오기에서 제목·시간·설명을 확인하고 저장할 수 있는가? |
| M09 | 실제 알림 받기 | 휴대폰에서 알림을 실제로 받았는가? 일정 저장 성공과 알림 수신 성공을 별도로 기록한다. |
| M10 | 일정 완료 | 상태 관찰·오늘 날짜·가상 메모로 완료하면 예정 목록에서 빠지고 완료 이력과 관리 기록 1건으로 남는가? |
| M11 | 별도 일정 수정·취소 | 본인 시험 일정을 하나 더 만들어 수정·취소하고, 실제 관리 기록은 늘지 않는지 확인한다. |
| M12 | 메뉴·탭·스크롤·키보드 | 메뉴 열기/닫기·맨 위로·세 상단 탭·상세 네 탭·사진 선택·키보드가 화면을 가리거나 가로로 넘치지 않는가? 느리면 대략 걸린 시간을 적는다. |
| M13 | 개인 정원 분리·다른 기기 | A 자료가 B에게 보이지 않는가? 같은 계정의 다른 기기에서는 **내 기록 새로고침**으로 보이는가? 로그아웃 후 이전 사진·입력·비교·백업이 남지 않는가? |

M03–M05와 M07–M11은 본인 식물에서 수행합니다. M06은 AI 비교 예시 또는 본인에게 이미 저장된 분석을 읽기만 합니다.
캘린더 알림이 올 때까지 M11–M13을 진행할 수 있습니다. 자동 동기화가 없으므로 앱에서 완료·취소해도 캘린더 이벤트는 별도로 남습니다.
본인이 만든 캘린더 테스트 일정은 테스트가 끝난 뒤 본인 캘린더에서 정리합니다.

### 담당자 한 명이 진행할 AI 연결 과제

**A01: AI 제안 선택 → 짧은 제목의 일정 초안 → 날짜·관리 종류·조건 확인 → 저장 → 캘린더 설명 → 완료 → 실행 후 경과**를 확인합니다.
같은 제안에는 예정 일정 한 건과 실행 한 건만 연결할 수 있으므로 같은 계정의 여러 기기에서 같은 제안을 반복해서 실행하지 않습니다.
담당자가 본인 정원의 저장된 미실행 제안을 하나 선택하고 가상 기록임을 표시합니다. 사용할 제안이 없으면 보류하고 팀장에게 알립니다.
테스트를 위해 새 Gemini 분석을 무조건 호출하지 않습니다. 실제 AI 요청은 아래 평가 담당자와 호출 횟수를 먼저 정합니다.

확인할 결과는 다음과 같습니다.

- 새 일정 제목이 짧고 직접 수정 가능하며, 설명에 원래 제안·모든 확인 조건·분석 한계·메모가 들어갑니다.
- 종류·날짜·확인 체크 없이 일정이 자동 저장되지 않습니다.
- 완료는 관리 기록 1건과 원래 제안의 실행 기록으로 연결됩니다. 물주지 않았다면 상태 관찰을 선택합니다.
- **관리 기록 → 실행 후 경과**에서 같은 제안을 선택해 오늘 실제 관찰 또는 가상 테스트 내용을 남깁니다. 미확인은 미확인으로 둡니다.
- **한눈에 보기 → 제안 이후의 변화**에서 실행 기록과 이후 관찰을 함께 찾고, 새로고침 후에도 유지되는지 확인합니다.

2026-10-15 개발 확인에서는 예시 몬스테라의 테스트 일정 완료와 경과 1건 연결, 새로고침 후 보존을 확인했습니다.
이는 팀원 기기별 테스트나 실제 식물의 관리 효과 검증 결과를 대신하지 않습니다. 자세한 캘린더 제한은 [케어 일정 안내](CARE_SCHEDULES.md)를 참고하세요.

## 빠르게 둘러보는 과제

가능하면 휴대폰에서 먼저 사용하고, 설명을 듣기 전에 아래 과제를 따라 해보세요.

| 과제 | 화면에서 할 일 | 남길 피드백 |
|---|---|---|
| 식물 찾기 | 내 정원에서 카드를 열어 마지막 물주기·관리 기록 찾기 | 찾는 데 걸린 대략적인 시간, 헷갈린 이름 |
| 등록·기록 | 새 식물을 등록하고 오늘 상태·메모 저장하기 | 필수 입력, 저장 버튼, 완료 표시를 이해했는지 |
| AI 안내 읽기 | 저장된 분석의 새싹 안내·확인 카드·관리·한계·전체 분석 펼쳐보기 | 먼저 무엇을 확인해야 하는지 자신의 말로 설명 |
| 제안 연결 | 관리 제안의 **관리 기록 남기기**를 눌러 연결한 제안 확인하기 | 일반 기록과 제안 실행의 차이를 알겠는지 |
| 다시 확인 | 내 정원으로 돌아가 기록 조회, 필요하면 새로고침 | 입력한 내용이 남아 있는지, 가로 스크롤·잘림이 있는지 |

제안 버튼을 누르는 것만으로 실행이 저장되지는 않습니다. 실제로 한 관리만 실행으로 기록하세요.
시험용으로 저장할 때는 메모에 가상 기록임을 명시합니다. 이후 경과도 관찰한 내용만 남깁니다.
사진은 선택입니다. 저장된 분석을 읽는 과제는 Gemini를 새로 호출하지 않습니다.
AI 안내 읽기·제안 연결 과제는 저장된 분석이 있는 예시 식물에서 진행할 수 있습니다.

## AI 제안 평가

**AI 비교 → 예시 사례**에는 젖은 흙, 마른 흙, 이전 관리 후 경과가 있는 세 상황이 있습니다.
AI를 호출할 차례와 담당자는 팀에서 먼저 정하세요. 같은 프로젝트의 한도를 함께 사용합니다.
상단 세 탭은 브라우저에서 바로 전환하고, 탭만 바꿀 때 작성 중인 입력과 비교 결과를 유지합니다. 전환 자체는 기록을 새로 읽거나 AI를 호출하지 않습니다.
다른 기기에서 본인 계정으로 남긴 기록은 메뉴의 **내 기록 새로고침**으로 불러옵니다. 식물 선택 등으로 서버가 다시 실행되면 마지막 조회 후 15초까지 기록을 재사용합니다.
AI 분석·내 기록으로 비교 준비·전체 백업 준비에서는 최신 기록을 다시 읽습니다. 새로고침 버튼을 눌러도 이미 고정한 비교 입력은 바뀌지 않습니다.

1. 한 사례를 선택하고 **비교 준비**로 입력을 고정합니다.
2. 입력과 Google 전송 안내를 확인한 뒤 동의합니다.
3. **기록 없이 분석**, **기록 포함 분석**을 각각 요청합니다. 둘 다 실행하면 총 2회입니다.
4. 아래 기준으로 두 답변을 읽고 화면의 평가와 이유를 남깁니다.
5. 새로고침·새 실험 전에 **비교 기록 내려받기**로 보관합니다. 사진을 썼다면 사진도 따로 내려받습니다.

| 평가 기준 | 확인할 질문 |
|---|---|
| 기록 반영 | 물 준 시점·실제 실행·경과를 맞게 읽었나요? 미확인을 실패나 완료로 바꾸지 않았나요? |
| 없는 사실 | 보지 않은 사진·측정하지 않은 흙 수분·확인하지 않은 회복이나 병명을 사실처럼 말하나요? |
| 확인 조건 | 물주기 전에 무엇을 확인하고, 어떤 경우에 어떤 행동을 해야 하는지 알 수 있나요? |
| 이해도 | 새싹 안내와 카드를 읽고 다음 행동을 설명할 수 있나요? 펼쳐보기에서 근거와 한계를 찾을 수 있나요? |

기록 포함 답변이 무조건 더 좋다고 평가하지 않습니다. 사례별 문제가 있는 문장과 이유를 남겨 주세요.
사용자의 이해도 평가, 원예 자료와 내용 비교, 실제 식물의 여러 날 관찰은 서로 다른 검증입니다.
가상 입력에 대한 답변이나 한 번의 호전 기록을 실제 진단 정확도·회복 효과로 발표하지 않습니다.
자세한 입력 통제와 한계는 [AI 비교 안내](AI_COMPARISON.md)에 있습니다.

## 문제가 생기면

| 상황 | 먼저 할 일 |
|---|---|
| 접속 권한·로그인 안내 | 이메일 인증·SMTP·메일 한도를 관리자에게 확인하기 |
| AI 버튼 비활성 또는 키 설정 안내 | 공유 앱의 관리자가 서버 설정 확인. 팀원이 키를 채팅에 보내지 않기 |
| 429 한도 오류 | 화면의 원인·대기 안내 기록, 담당자가 프로젝트 한도 확인. 버튼 연속 클릭 피하기 |
| 시간 초과·응답 실패 | 자동 재시도하지 않음. 요청이 서버에서 처리됐을 수 있으므로 담당자와 재요청 여부 정하기 |
| 저장 충돌·결과 불확실 | 메모를 개인적으로 복사해 두고, 메뉴의 **내 기록 새로고침** 후 기록이 이미 있는지 먼저 확인 |
| 사진이 안 보임·저장소 오류 | 화면의 안내와 발생 시각을 관리자에게 전달. 기존 기록을 다시 등록하지 않기 |

공유 앱의 API 키·저장소·접근 설정은 관리자가 담당합니다.
백업은 **기록 보관과 백업**에서 전체 정원 ZIP으로 준비합니다. 개인 기록이 포함되므로 공개 저장소에 올리지 않습니다.
비교 실험은 이 ZIP에 포함되지 않으며 별도로 내려받아야 합니다.

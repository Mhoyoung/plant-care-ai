# 팀 정원의 기록과 사진을 외부 저장소에 보관하기

Streamlit 서버의 로컬 파일은 재배포·재시작 후 보관이 보장되지 않습니다.
Supabase의 PostgreSQL과 비공개 Storage에 정원을 보관하면 앱 서버가 새로 시작해도 기록과 사진을 다시 불러올 수 있습니다.
하나의 팀 정원을 함께 사용하며, 개인별 정원·역할 분리는 아직 구현하지 않았습니다.

## 1. 기존 정원 전체 백업

저장소를 바꾸기 **전에** 기존 앱 왼쪽 **기록 보관과 백업 → 사진 포함 전체 백업 준비 → 정원 전체 백업 내려받기**를 사용합니다.
`plant-care-garden.zip`에는 기록과 사진이 모두 포함됩니다. 식물별 JSON에는 사진이 없으므로 전체 ZIP을 내려받으세요.
백업은 공개 GitHub나 채팅에 올리지 않습니다. 이후 기록은 다시 백업해야 합니다.

## 2. 전용 무료 프로젝트 준비

1. [Supabase Dashboard](https://supabase.com/dashboard)에 로그인합니다.
2. 전용 Free 프로젝트를 만들고 가능하면 한국 리전을 선택합니다. DB 비밀번호는 본인이 직접 정합니다.
3. **SQL Editor → New query**에서 [setup.sql](../supabase/setup.sql)의 전체 내용을 실행합니다.
4. `pc_gardens`, `pc_garden_writes`와 **비공개** `plant-care-photos` 버킷이 생성됐는지 확인합니다.

SQL은 기존 데이터를 덮어쓰지 않습니다. 같은 파일을 다시 실행해도 기존 정원은 유지합니다.
일반 공개 키와 로그인 사용자에게는 테이블·RPC 접근을 허용하지 않습니다. 서버용 키만 접근합니다.
사진 버킷이 공개로 되어 있다면 앱 연결을 거부합니다.

## 3. Streamlit Secrets 설정

앱의 **Sharing**은 **Only specific people can view this app**으로 유지합니다.
Supabase **Settings → API Keys**에서 **Secret key (`sb_secret_...`)**를 확인합니다.
Publishable key는 사용하지 않습니다. Secret key는 전용 앱 서버에서만 사용하고, 키 자체를 채팅·GitHub·사진으로 공유하지 않습니다.

Streamlit 앱 설정의 **Secrets**에 기존 Gemini 설정을 유지한 채 추가합니다.

```toml
GEMINI_API_KEY = "기존 Gemini 키"
STORAGE_BACKEND = "supabase"
SUPABASE_URL = "https://프로젝트참조.supabase.co"
SUPABASE_SECRET_KEY = "sb_secret_로 시작하는 서버용 키"
```

URL은 Supabase 프로젝트 화면의 Project URL입니다. 실제 키는 본인이 이 비밀 설정 화면에 직접 입력합니다.
키는 Python 서버의 `apikey` 헤더에서만 사용하며 사진의 공개 URL이나 AI 입력에는 넣지 않습니다.
앱이 저장소 오류를 표시하면 URL·키·SQL 설정과 Supabase 일시정지 여부를 확인합니다. 연결 실패 시 로컬 저장으로 자동 전환하지 않습니다.
이 설정은 팀원이 접속하는 공유 앱에 먼저 적용합니다. 개인 PC는 `STORAGE_BACKEND = "local"`로 별도 정원을 유지할 수 있습니다.

## 4. 기존 기록 가져오기와 확인

1. 외부 저장소 연결 후 앱에서 **기록 보관과 백업**을 펼칩니다.
2. 비어 있는 정원에서 전체 백업 ZIP을 올립니다.
3. Supabase로 기록·사진을 옮기는 전송 안내를 체크하고 **기존 정원 가져오기**를 누릅니다.
4. 식물 이름·기록·AI 분석·지역 설정과 사진을 확인합니다.
5. 새로고침과 다른 브라우저에서 같은 기록이 보이는지 확인합니다. 팀원은 기존 초대 계정으로 접속합니다.
6. 앱 서버를 재시작한 뒤 기록과 사진을 다시 확인합니다. 이 실제 확인까지 끝나야 배포 연결 완료로 봅니다.

기록이 이미 있는 정원에는 백업을 덮어쓰지 않습니다. 원래 기록 ID·날짜·분석 당시 입력·제안 연결을 유지합니다.
전환 후 빈 정원이 보이는 것은 기존 로컬 데이터를 자동으로 삭제하거나 이전한 것이 아닙니다. 내려받은 전체 ZIP으로 명시적으로 가져옵니다.

## 저장과 동시 사용

소규모 팀 테스트용으로 전체 정원을 하나의 버전 있는 JSONB 스냅샷으로 보관합니다.
화면 실행마다 원격 최신 스냅샷을 임시 SQLite로 복원해 기존 검증·조회 코드를 사용하고, 변경 시 PostgreSQL 트랜잭션으로 저장 버전을 비교합니다.
두 팀원이 같은 버전을 수정하면 먼저 저장한 기록을 유지하고 뒤의 저장에 새로고침 안내를 표시합니다. 자동으로 덮어쓰거나 재시도하지 않습니다.
대규모 데이터·개인별 정원으로 확장할 때는 행 단위 DB 구조와 사용자별 권한으로 옮깁니다.

쓰기 ID 이력을 함께 저장합니다. 응답이 끊기면 해당 쓰기의 완료 여부만 조회하며, 확인되지 않은 쓰기는 성공이라고 표시하지 않습니다.
사진은 UUID 이름의 비공개 객체입니다. 사진 업로드와 DB 커밋은 별개라 실패 시 미참조 사진이 남을 수 있습니다.
커밋 결과가 불확실할 때 실제 기록의 사진을 삭제하지 않기 위해 자동 삭제하지 않습니다. 장기 사용 시 관리자의 미참조 사진 정리 절차가 필요합니다.
사진 조회 실패 시 기록을 유지하고 재연결 안내를 표시합니다.

정원 스냅샷은 최대 16MB, 앱에서 준비하는 전체 백업은 최대 100MB입니다. 표시한 한도는 앱의 제한이며 서비스 요금제 한도와 다릅니다.
백업에는 비밀키가 포함되지 않습니다. JSON 및 사진의 경로·크기·연결을 검증하고 ZIP을 임의 파일 경로로 풀지 않습니다.

## 무료 구간과 백업

2026-10-12 공식 요금표에서 Free의 DB 500MB·파일 저장 1GB를 확인했습니다. 사용 조건과 한도는 변경될 수 있습니다.
활동이 적은 무료 프로젝트는 일주일 정도 지나면 일시정지될 수 있어 대시보드에서 Resume이 필요할 수 있습니다.
Free는 다운로드 가능한 자동 DB 백업을 제공하지 않으므로 앱의 전체 ZIP을 주기적으로 내려받아 별도 보관하세요.
서버 재시작 후 유지와 백업·장애 복구는 별개의 기능입니다.

## 검증 범위

모의 Supabase로 기록·사진·관리 흐름의 재접속, 동시 저장 충돌, 커밋 후 응답 유실, 백업 이전·덮어쓰기 거부와 키 오류 숨김을 검증합니다.
실제 프로젝트에서는 SQL 실행, 비공개 접근, 앱의 데이터 이전과 재시작 후 보존을 추가 확인합니다.
계정·프로젝트 설정이 준비되기 전에는 모의 검증만으로 실제 연결 완료를 표시하지 않습니다.
